Raddex is a reverse-proxy gateway built on
[Cloudflare Pingora](https://github.com/cloudflare/pingora). It provides one
readable configuration file for HTTP/HTTPS routing, automatic TLS, static
files, upstream balancing, and selected TCP/UDP services.

## Why Raddex?

- **Predictable configuration.** Site directives follow the order you write;
  there is no hidden global ordering table.
- **Automatic HTTPS.** ACME HTTP-01, Cloudflare DNS-01, and TLS-ALPN-01 are
  available alongside static certificates, internal certificates, and mTLS.
  TLS-ALPN-01 is limited to eligible ACME sites on port 443 and cannot be
  combined with DNS-01.
- **A small operational surface.** Validate with `raddex check`, reload with
  SIGHUP, and upgrade the binary without dropping the listener topology.
- **A clear protocol boundary.** Raddex can pass UDP traffic, including QUIC
  datagrams, but HTTP/3 termination remains a separate QUIC service.

## What is included in v0.3.5?

| Capability | Release status |
| --- | --- |
| HTTP/1.1 and downstream HTTP/2 | Supported |
| Upstream HTTP/1.1, `https://`, `h2://`, and `h2c://` | Supported |
| Multiple domains, IPv6, exact and one-label wildcard matching | Supported |
| Static files, compression, auth guards, rate limits, logs, and metrics | Supported |
| TCP, SNI passthrough, TCP TLS termination, and UDP proxying | Supported |
| Transparent TCP and UDP flow handoff | Linux-only |
| QUIC / HTTP/3 termination | Separate sidecar required |

Raddex is still pre-1.0. "Supported" means the behavior is implemented and
covered by the v0.3.5 verification suite; consult the [capability matrix](architecture/capabilities/)
for deployment prerequisites and exclusions.
