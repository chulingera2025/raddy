Raddex 是用 Rust 编写的反向代理网关。它通过一份可读的配置文件统一承载
HTTP/HTTPS 路由、自动 TLS、静态文件、上游负载均衡，以及经过严格边界约束的
TCP/UDP 四层代理服务。

## 为什么选择 Raddex？

- **配置行为可预测。** 站点块内的指令严格按书写顺序执行，没有隐式的全局排序表。
- **开箱即用的自动 HTTPS。** 原生支持 ACME HTTP-01、Cloudflare DNS-01 与 TLS-ALPN-01，
  同时支持静态证书、内部自签证书与 mTLS。TLS-ALPN-01 仅限 443 端口上符合条件的 ACME 站点，且不能与 DNS-01 混用。
- **运维开销轻量。** 使用 `raddex check` 预检配置，通过 SIGHUP 原子重载路由快照，支持无中断热升级二进制。
- **清晰的协议与架构边界。** HTTP 核心运行在 Pingora 上，四层（TCP/UDP）运行在独立的原生 Tokio 数据面上；支持 UDP/QUIC 数据报透传，但 QUIC/HTTP-3 终止保持为独立的 sidecar 边界。

## v0.3.6 包含哪些能力？

| 能力 | 发布状态 |
| --- | --- |
| HTTP/1.1 与下游 HTTP/2 | 支持 |
| 上游 HTTP/1.1、`https://`、`h2://` 与 `h2c://` | 支持 |
| 多域名、IPv6、精确与单标签通配符匹配 | 支持 |
| 静态文件、流式压缩、认证守卫、单机限流、日志与指标 | 支持 |
| TCP 代理、SNI 透传、TCP TLS 终止与 UDP 流代理 | 支持 |
| Linux 透明 TCP 与 UDP flow 升级交接 | 仅限 Linux |
| QUIC / HTTP/3 终止 | 需要独立 sidecar |

Raddex 目前尚未达到 1.0。「支持」代表该行为已在 v0.3.6 验证套件中通过测试；部署前置条件与边界说明详见 [能力矩阵](architecture/capabilities/)。
