Raddex 是基于 [Cloudflare Pingora](https://github.com/cloudflare/pingora) 构建的
反向代理网关(Rust)——Pingora 正是为 Cloudflare 边缘网络提供动力的代理框架。
你只需写一份 **Raddexfile**(Caddyfile 风格的配置),raddex 便负责路由、自动
HTTPS、静态文件、压缩、限流与访问日志,并享有 Pingora 的性能与内存安全。

结果是一个单一的小型二进制,做反向代理该做的事——配置可读、行为可预测。

## 为什么选 Raddex

- **天生高速。** raddex 构建于 Pingora:多线程事件循环、共享连接池、无垃圾
  回收。相对裸 Pingora,代理热路径只增加极小开销。
- **配置可以推理。** 指令**严格按书写顺序**执行。所见即所执行——没有隐藏的
  指令排序表。每条指令要么是终端("谁服务这个请求"),要么是修饰符
  ("如何服务"),要么是守卫("谁可以被服务")。
- **开箱即用的生产级 TLS。** 基于 ACME 的自动 HTTPS(HTTP-01 或 DNS-01)、
  SNI 证书选择、按站点的 TLS 选项、双向 TLS,以及下游 HTTP/2。
- **零停机运维。** SIGHUP 重载原子替换路由快照;`raddex upgrade` 将监听套接字
  移交给新二进制,连接零中断。
- **默认安全。** 未经声明不信任任何东西:raddex 在配置 `trusted_proxies` 之前
  忽略 `X-Forwarded-For`;无法读取的凭据会失败关闭(fail closed)。

## 功能亮点

- **路由与匹配** —— 按 `path`、`host`、`method`、`header`、`query`、
  `remote_ip` 或 `protocol` 路由,支持 `!` 取反与空格分隔的 AND 条件;
  `handle`、`handle_path`、`rewrite`、`respond`、`error` 让你精确控制每个请求
  由谁服务。
- **反向代理** —— 单个或多个上游,轮询 / 随机 / IP 哈希负载均衡,主动健康
  检查,**到后端的 TLS**(`https://` 上游,含 SNI、自定义 CA 与客户端证书),
  以及透明的 **WebSocket** 升级转发。
- **自动 HTTPS** —— 经 HTTP-01 或 DNS-01 签发 ACME 证书并自动续期;另有
  `tls` 指令支持自签(`internal`)、静态证书、协议版本与密码套件限制,以及
  **mTLS** 客户端认证。
- **认证守卫** —— `basic_auth`(bcrypt 哈希)与 `forward_auth`(交给专用认证
  上游)。
- **压缩** —— gzip、zstd 与 **Brotli**(`encode br`),按客户端的
  `Accept-Encoding` 协商。
- **限流** —— 基于真实客户端 IP 或任意请求头的令牌桶限制。
- **静态文件** —— `file_server` 支持索引文件、路径穿越防护与压缩。
- **配置 DX** —— 多文件 `import`、可复用的 `(name)` 片段,以及 `{$ENV}`
  变量替换。
- **可观测性** —— Prometheus 指标、JSON 或 Common Log Format 访问日志,可按
  站点配置。

## 何时使用 raddex

当你想用一个又小又快的、可预测的反向代理时,raddex 很合适:

- 把一个或多个 HTTP/HTTPS 服务放到公网并自动启用 TLS。
- 在单个进程中同时托管静态内容与代理 API。
- 用 `raddex check` 校验、用 SIGHUP 重载的配置文件,精确掌控路由、限流与认证。

raddex 是**单实例**的:限流按进程计数,不跨集群共享。如果你需要跨集群协调、
外部共享服务或插件系统,更大的代理更合适。
